## Context

現在の `KeyGuide` コンポーネントはフッター内にトグル付きテーブルとして実装されており、9件の基本キーのみ記載されている。レイアウト上は入力エリアと縦に重なるため、参照しながら入力することができない。また `Tab` / `x` / `Shift+Tab`（前候補）、記号変換、単語登録などエンジンに実装済みのキーバインドが未掲載。

## Goals / Non-Goals

**Goals:**
- 広い画面では入力エリア右にサイドパネルとして常時表示する
- キーガイドの内容を6セクションに拡充し、実装済みの全キーバインドを網羅する
- 狭い画面（`max-width: 900px` 程度を目安）では基本セクションのみをフォーム下部に表示する（縦レイアウトフォールバック）
- ⚠️ IME注意書きをキーガイドから切り出して入力欄の直上に移動する

**Non-Goals:**
- モバイル向けの最適化（スクロール・タッチ操作など）
- フェーズ連動型の動的キーガイド（案B）
- パネルの開閉トグル（広い画面では常時表示）

## Decisions

### レイアウト: CSS Grid によるサイドバイサイド

広い画面のレイアウトを CSS Grid で構成する。`App.tsx` のフリー入力エリア（`app__main` 内）を `grid-template-columns: 1fr auto` のラッパーで囲い、左カラムに入力エリア、右カラムにサイドパネルを配置する。

**代替案**: Flexbox でも実現可能だが、将来的なカラム幅調整を考えると Grid のほうが明示的。

**レスポンシブ**: メディアクエリ（`max-width: 900px`）でグリッドを解除し、縦積みに戻す。狭い画面では `KeyGuide` の詳細セクションを CSS で非表示にする（`display: none`）か、`props` でモードを切り替える。CSS クラスで制御するほうがシンプルなため採用。

### KeyGuide コンポーネント: `variant` prop で表示モードを切り替えない

CSS メディアクエリのみで表示を制御し、JS 側で `variant` を渡す設計はしない。コンポーネントは常に全セクションをレンダリングし、狭い画面では詳細セクションを CSS `display: none` で隠す。React の状態管理を増やさずシンプルに保てる。

### トグルボタン: 廃止

現在の折りたたみトグル（`useState(open)`）は不要になるため削除する。広い画面では常時表示、狭い画面では基本セクションを固定表示。

### IME注意書きの移動先

`SkkInputArea.tsx` 内ではなく `App.tsx` のフリー入力エリア部分（入力欄の直上）に inline で配置する。`SkkInputArea` は純粋な入力コンポーネントとして維持し、注意書きなどの contextual UI は親で管理する。

## Risks / Trade-offs

- **CSS Grid のブレークポイント** → `900px` は暫定値。実際に表示してみて調整が必要な場合あり。
- **キーガイドのコンテンツ量** → 詳細セクションが増えた場合、パネルがスクロールになることがある。パネルを `overflow-y: auto` + `max-height` で制御する。
- **折りたたみ廃止** → 現在デフォルトで開いているため、ユーザーが閉じて使っていたケースには影響するが、サイドパネルになることで邪魔になりにくく許容範囲と判断。
